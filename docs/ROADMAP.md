# Дорожная карта

Номер этапа - это номер работы, а не версия приложения. Версию APK (`versionName`, `versionCode`) задаёт сборка, и она с этапами не связана.

**Цель первой рабочей версии:** пользователь включает приложение на Pixel 7 в сети Билайн - и YouTube в Chrome открывается сам, без настроек. Остальные возможности добавляются после того, как эта цель достигнута и проверена на телефоне.

Правило против бесконечного исследования: каждый этап заканчивается проверкой на Pixel 7; новый изолированный компонент не начинается, пока предыдущий не работает в реальном тракте.

## Разбор задач для исполнителя

Таблицы выше - перечень задач и критерии. Этот раздел - инструкция исполнителю (человеку или модели): по каждой задаче цель, что прочитать, шаги в обязательном порядке, файлы, тесты, условие «готово», запреты и влияние на общий код. Если шаг невозможен так, как написан, исполнитель останавливается и называет причину (п. 35, 51 AGENTS.md), а не заменяет шаг своим решением.

### Общие правила для всех задач

1. **Чтение до правок** (п. 48): документы, названные в задаче, - целиком; затрагиваемые файлы - целиком; тесты этих файлов - целиком.
2. **Анализ, а не шаблоны** (пп. 5, 52, инвариант 11): ни одна задача не добавляет список готовых мер, перебор комбинаций или «стратегию по умолчанию». Мера появляется только из установленного факта профиля ([ENGINE.md](ENGINE.md), разделы 7, 22, 28). Пресеты byedpi и zapret - только начальные веса гипотез. Если в коде появляется массив мер, который перебирается по очереди, - задача сделана неверно.
3. **Числа** - только из [ENGINE.md](ENGINE.md) раздел 21, [TRANSPORT.md](TRANSPORT.md) или из измерения с записью, где измерено. Новое число без источника - ошибка.
4. **Код** - новые классы в новых файлах и пакетах из «Реализации модулей» [ARCHITECTURE.md](ARCHITECTURE.md); существующие файлы не переносятся и не переименовываются (п. 24); направление зависимостей `:app` → `:vpn` → `:engine`, `:analysis`; `:engine` и `:analysis` друг от друга не зависят.
5. **API Android** - только доступные при `minSdk 29`, более новые - под `Build.VERSION.SDK_INT`; каждая сигнатура сверяется с документацией Android до использования (п. 29).
6. **Формат сохранённых данных, манифест, публичные интерфейсы модулей** - каждое изменение называется в отчёте отдельно (п. 27).
7. **Проверка** (пп. 30, 45, 54): `testDebugUnitTest :engine:test` (после появления - `:analysis:test`) и `assembleDebug`; для общего транспортного кода (`HevLoopbackRelay`, `OutboundTransport`, `AdaptiveVpnService`, мост HEV) - базовый и расширенный наборы AVD в CI. **Шаги.**

### Этап 3. Полный анализ

#### 3.1 Анализ вариантов
Шаги: минимальная пара (блокируемый вариант и вариант с нейтральным именем на тот же адрес); деление различий пополам по признакам `Variant` (параметрические пробы, K повторов на точку, нестабильная точка останавливает поиск); уточнение имени (уровень суффикса, регистр); правило DPI как факт с областью «класс ключей»; проверка предсказанием на другом имени того же класса без нового поиска; предсказание меры для новых ключей с первого отказа (раздел 14) с учётом ошибки предсказания; путь `unknown` (раздел 23): описание аномалии, ограниченная проверка - не больше одной меры на свойство из параметрических моделей каталога, экспорт протокола аномалии. Тесты: стенд `sni-suffix` (вторая цель получает меру со второго соединения), `residual`, модель вне каталога даёт `unknown` и протокол.

#### 3.2 Вопросы В5-В8 и нативные операции
Шаги: `tcp-split-guaranteed` (`notSent` из 1.6, шаг 1 мс, не дольше 50 мс, иначе пометка «не гарантирован»); `disorder` (TTL из факта, гарантированный разрез, восстановление TTL); параметрический поиск TTL 1-32 двоичным поиском с областью факта «адрес или префикс» и критерием из раздела 20; В5 (сборка сегментов), В6 (порог объёма), В7 (генератор QUIC Initial с целевым SNI - обратная операция к 2.4b), полный В8. Тесты: PCAP на стенде подтверждает форму; модели `sni-stream`, `sni-drop`, `volume`, `quic-block` различаются.

#### 3.3 Слежение за изменениями DPI
Шаги: при деградации ключа с мерой - сначала одна различающая проба по факту меры; изменился - диагноз заново; нет - соседние причины (В1, В2); запасные меры только из других фактов того же ключа; `DpiChange` в журнал изменений; несколько профилей на одной сети при совпадении деградации со сменой подписи. Тест: стенд меняет модель `sni-first-record` → `sni-stream` во время работы.

#### 3.4 Хранение профилей
Шаги: `ProfileStore` (интерфейс в `:analysis`, реализация в `:vpn`): файлы `profiles.json`, `keys.json`, `overrides.json`, `budgets.json`, `capabilities.json` в `filesDir/analysis/`, поле `schema`, запись во временный файл и `Files.move(..., ATOMIC_MOVE)`; не чаще раза в 5 с и при остановке VPN; вытеснение - до 500 ключей на подпись сети (порядок из раздела 20), профили не встречавшихся 30 дней сетей удаляются; подпись сети - пассивная часть и ленивая проверка фактов. Новый формат хранения называется в отчёте (п. 27). Тесты: перезапуск процесса (новый экземпляр с тем же каталогом) не теряет профиль; повреждённый файл - профиль пустой, ошибка в журнале, приложение работает; другая подпись - новый профиль.

#### 3.5 Старение, отложенные задачи, антидребезг
Шаги: +1 уровень приоритета через 10 минут ожидания; задачи от фоновых приложений при выключенном экране без зарядки откладываются (`PowerManager.isInteractive`, `BatteryManager` - через интерфейс в `:analysis`); повторы `Unsolved` - при смене подписи сети после 5 минут стабильности, затем 1 ч, 6 ч, 24 ч. Тесты: JVM на порядок выдачи слотов; переключения сети каждые 30 с не порождают повторов.

#### 3.6 Fake через `vmsplice`
Условие начала: 1.6 показал, что `vmsplice`/`splice` разрешены на Pixel 7, **и** этап 0 или протоколы проб показали, что меры уровней записей и сегментов не работают. Иначе задача не начинается. Шаги: `sendFake` по схеме byedpi `send_fake` с сохранением уведомления MIT (п. 14); содержимое ложной части - параметрическая проба (`neutral-hello`, `clone-renamed`, `random`); `md5-fake` - если `TCP_MD5SIG` разрешён. Тесты: стенд с PCAP (ложная часть не дошла до сервера, П2 проходит); Pixel 7.

#### 3.7 Лаборатория
Шаги: в разделе разработчика - выбор ресурса, ручной запуск вопроса или варианта, редактор признаков `Variant`, сравнение двух вариантов, пошаговое деление пополам; всё через общий актор и бюджеты. Готово: ручной запуск на Pixel 7 в пределах бюджета.

#### 3.8 Самотест возможностей
Шаги: `CapabilitySelfTest` в `:vpn`: функции 1.6 на loopback-паре при первом запуске и при смене `Build.FINGERPRINT`; результат в `capabilities.json`; синтез видит только операции с `ok`. Тест: на Pixel 7 результат совпадает с таблицей эксперимента 1.6.

#### 3.9 Экспорт и импорт
Шаги: `BackupCodec` в `:app` (модуль подключает плагин и `libs.serialization.json`); виды `backup` и `network-knowledge` по структуре файла из [ARCHITECTURE.md](ARCHITECTURE.md); лимит 5 МБ; проверка схемы; файл новее схемы - отказ; миграции по номеру; дубли по тройке «подпись - механизм - область» для фактов и паре «ключ - набор операций» для мер, для настроек остаётся локальное; импортированный факт - с пометкой и как начальный вес; меры проверяются по `DeviceCapabilities`; транзакция «разобрать всё, затем одна запись»; отчёт импорта; отправка через `SendButton`. Тесты: `BackupCodecTest` - повторный импорт 0 добавлено; противоречащий факт - конкурирующая гипотеза; неизвестная операция отклоняет запись; файл новее схемы.
