# Дорожная карта

Номер этапа - это номер работы, а не версия приложения. Версию APK (`versionName`, `versionCode`) задаёт сборка, и она с этапами не связана.

**Цель первой рабочей версии:** пользователь включает приложение на Pixel 7 в сети Билайн - и YouTube в Chrome открывается сам, без настроек. Остальные возможности добавляются после того, как эта цель достигнута и проверена на телефоне.

Правило против бесконечного исследования: каждый этап заканчивается проверкой на Pixel 7; новый изолированный компонент не начинается, пока предыдущий не работает в реальном тракте.

### Этап 1

**1.1 Квота релея до аутентификации** - сделано в `feat/stage1` (`8de3f1d`), ждёт CI.
Шаги, уже выполненные: приём без слота; лимит неаутентифицированных `maxSessions/2` (минимум 2) с вытеснением старейшего; слот после аутентификации, ожидание до 5 с; пул запросов `maxSessions + preAuthLimit`. Файлы: `HevLoopbackRelay.kt`, `HevLoopbackRelayTest.kt`, [TRANSPORT.md](TRANSPORT.md). Осталось: зелёный CI (JVM, базовый и расширенный AVD). Влияние: число потоков до 80 при 32 слотах; ответ на CONNECT приходит только после получения слота.

**1.3 Проба ресурса различает причины.**
1. Прочитать `vpn/.../diagnostics/ResourceProbe.kt`, `ResourceProbeTest.kt`, `engine/.../TransportFailure.kt` и [TRANSPORT.md](TRANSPORT.md) (RelayWait).
2. Ввести раздельные статусы TLS: сертификат не прошёл проверку, сброс (`ECONNRESET`), тишина после ClientHello, TLS alert, успех. Статус - значение `enum`, а не строка.
3. Ошибки классифицировать через `TransportFailureReporter`, а не отдельной веткой кода.
4. DNS - через `DnsResolver.query(Network, …, CancellationSignal, …)` (API 29); проверить сигнатуру по документации Android до написания.
5. Привязать сокет и DNS-запрос к физической сети; семейство IP явное, по умолчанию IPv4.
6. HTTP-уровень: `451` - отдельный статус «ограничение на стороне сервера»; `403` - «отказ сервера» без вывода о причине; редирект на чужой домен второго уровня - «заглушка»; хост цели редиректа не следовать, а записать.
