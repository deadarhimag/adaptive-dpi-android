# Проверка Adaptive DPI Android на Pixel 7

Понадобятся компьютер с Windows, Python 3.10 или новее и уже подключённый по ADB Wi-Fi Pixel 7. Подключите телефон и компьютер к одной доверенной локальной сети. Остановите действующий сеанс Adaptive DPI VPN в приложении и разблокируйте телефон. Тест запускает два коротких сеанса VPN с маршрутом только к компьютеру.

## Скачать сборку

1. Войдите в GitHub и откройте последнюю успешную [«Сборку Android»](https://github.com/deadarhimag/adaptive-dpi-android/actions/workflows/android-build.yml) из ветки `main`.
2. Внизу страницы запуска в разделе **Artifacts** скачайте `adaptive-dpi-android-debug-…`. Распакуйте архив целиком.
3. В архиве лежат `app-debug.apk`, `app-debug-androidTest.apk`, скрипт и сведения о сборке `build-info.txt` и `build-info.json`. APK тестов связан с приложением целевым пакетом и общим сертификатом. Выберите архив с кодом версии 25 или выше и успешными Android-тестами в `build-info.json`. Если проверку назначил разработчик, скачайте ровно указанный им запуск. В отчёт запишите ссылку на запуск, SHA и код версии из `build-info.txt`: результат относится только к этой сборке.

Скрипт сам установит оба APK при необходимости. Для установки только приложения можно перенести `app-debug.apk` на телефон, открыть его в приложении «Файлы» и подтвердить установку в Android.

## Запустить проверку

Откройте распакованную папку в Проводнике. Наберите `powershell` в адресной строке и нажмите Enter. В открывшемся окне выполните команду:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-pixel7.ps1 -TransportTarget 192.168.0.157
```

Если IPv4 компьютера изменился, подставьте актуальный адрес из параметров сети Windows. Параметр `-ExecutionPolicy Bypass` действует только для этого запуска PowerShell. На телефоне откроется экран проверки. Тест сам запустит и остановит два сеанса. Оставьте этот экран открытым. Если Android покажет системный запрос на VPN, нажмите **ОК** в течение двух минут. Доступность TCP, UDP и DNS сначала проверяется напрямую с телефона, затем через TUN.

Успешный результат начинается со слова **УСПЕХ**. В каждом из двух сеансов проверяются совпадение отправленных и полученных данных по TCP, UDP и DNS, счётчики пакетов в обоих направлениях и отсутствие активных соединений после остановки. Первый сеанс должен завершиться до запуска второго. Проверка использует синтетические данные локального стенда.

## Проверка обновления и сценариев на Pixel 7 с Android 17

Используйте подписанный CI-архив последней зелёной сборки. У предыдущих сборок подтверждён сертификат SHA‑256 `fcc54b93089dbf3467ec6c6edc6cd03766cdae5a6cb98e104fdb30b6ab9675de`. Сверьте его с `build-info.txt` новой сборки. При несовпадении прекратите проверку обновления и сохраните сведения о сборках. Android должен обновить приложение без потери данных при совпадающей подписи и большем `versionCode`.

## Проверить Chrome через транспорт приложений

1. Установите оба APK скриптом выше или обновите приложение файлом `app-debug.apk` из свежего архива. Сверьте сертификат и версию по шагу 1 приёмки.
2. Подключите Pixel 7 к Wi-Fi с IPv4 и DNS по IPv4. Откройте adaptive-dpi-android и остановите текущий сеанс, если он активен.
3. Откройте **Настройки → Для разработчика** и найдите **Трафик приложения · экспериментальный режим**. Оставьте `com.android.chrome` и нажмите **Запустить транспорт приложения**. Подтвердите системный запрос VPN, если он появится. Дождитесь статуса «Сетевой движок запущен».
4. Откройте в Chrome новую вкладку и загрузите доступный обычный HTTPS-сайт, например `https://example.com/`. Проверьте текст страницы. При повторе обновите страницу, чтобы проверить новый запрос. Откройте **Диагностику** в adaptive-dpi-android и убедитесь, что выросли счётчики пакетов и байтов в обе стороны.
5. Нажмите **Остановить VPN**. В диагностике должны быть ноль активных соединений и событие освобождения TUN. Запустите транспорт повторно и ещё раз загрузите HTTPS-страницу.

Этот сценарий проверяет обычный трафик Chrome. VPN захватывает IPv4 для выбранного пакета, включая IPv4 DNS физической сети. IPv6 для этого пакета блокируется. IPv6-only/NAT64, принудительный Private DNS и QUIC требуют отдельной проверки. При сбое сохраните общий отчёт через **Диагностика → Экспортировать диагностику**, укажите версию Android и тип подключения.

### Сохранить диагностику транспорта

Этот же диалог используется для общего отчёта через **Экспортировать диагностику** и для отдельной ошибки через **Технические подробности → Экспорт отчёта об ошибке**. Перед отправкой проверьте его текст. `VpnCleanupDelayed` содержит ID сеанса, наблюдавшийся этап и время ожидания. Итоговый снимок появляется после подтверждённого освобождения ресурсов. При реальной ошибке сохраните запись `VpnCleanupFailed` и журнал того же сеанса.

После повторной проверки Chrome и остановки VPN откройте **Диагностика → Сводка транспорта**. Сверьте итоговое количество отказов, разбивку по причинам и число отброшенных событий. Отмены блокирующих операций при остановке учитываются как ожидаемые. В разделе **Журнал транспорта → Экспорт журнала транспорта** нажмите **Сохранить**, чтобы выбрать место для `adaptive-dpi-transport.txt`, или **Поделиться**, чтобы отправить TXT через системное меню Android. Для проверки экспорта повторите оба действия и при работающем VPN. Откройте сохранённый файл и вложение в выбранном приложении. **Отмена** закрывает диалог. Общий отчёт по-прежнему доступен через **Экспортировать диагностику**. В двух отчётах есть коды, времена, направление операций, состояние VPN и повторения. Адреса, порты, DNS-ответы и содержимое трафика в журнал транспорта не попадают. Если системный код недоступен и причина не установлена, запись помечается `unknown`.

Для повторной проверки этапа 2.4 выполните два сеанса Chrome. Обновите страницу несколько раз, остановите VPN и дождитесь `Idle`. Проверьте ноль активных TCP/UDP-соединений, освобождение TUN и итоговую сводку по последнему сеансу. Повторите запуск сразу после остановки. По времени и идентификатору нового сеанса проверьте, что `WORKER_REJECTED` и `RELAY_STOP` отсутствуют при обычной загрузке, а у записей этого сеанса нет состояния `Idle`. `FLOW_CANCELLED` в `EngineRunning` означает отмену операции при явном закрытии отдельного сокета. `SESSION_CANCELLED` относится к остановке всего сеанса. Если сбой повторится, сохраните оба TXT из раздела диагностики.

## Если тест завершился ошибкой

- **Другой сертификат.** Для проверки обновления оставьте прежний пакет на телефоне. Найдите CI-архив с совпадающей подписью и сохраните диагностический отчёт. Локальный debug APK обычно подписан другим ключом. [Обновление приложений Android](https://developer.android.com/google/play/app-updates)
- **На телефоне более новая версия.** Возьмите архив из более свежего успешного запуска. Оба APK и `build-info.json` должны быть из одного архива.
- **Стенд недоступен.** Проверьте, что адрес принадлежит активному адаптеру ПК, телефон в той же сети, а точка доступа разрешает связи между устройствами. Разрешите Python входящие соединения в брандмауэре Windows для частной сети: TCP и UDP `39052`, UDP `39053`. Останавливать брандмауэр не требуется. Проверьте, что эти порты не заняты другим экземпляром стенда.
- **ADB не видит телефон.** Проверьте беспроводную отладку и соединение. Скрипт ищет `adb` в SDK и `PATH`. Если подключено несколько Pixel 7, передайте `-Serial` с адресом и портом нужного телефона.
- **Запрос VPN не подтверждён.** Разблокируйте телефон и запустите команду снова. При включённой системной блокировке подключений без VPN доступ к локальному стенду может быть ограничен настройками Android.

После запуска PowerShell выводит путь к папке `pixel7-logs-…`. При ошибке передайте эту папку и `build-info.txt` для анализа. В ней есть вывод теста `instrumentation.log`, журнал стенда `fixture.log` и, если доступно, отфильтрованный журнал Android `android.log`. Просмотрите файлы перед отправкой. Данных ключа подписи в артефакте и журналах нет.

## Проверить переключение с другого VPN

Используйте сборку с изменением переключения VPN и другое VPN-приложение, которое направляет трафик Adaptive DPI через себя.

1. Отключите другой VPN. Откройте Adaptive DPI и убедитесь, что открытие приложения само не запускает VPN. Запустите проверочный сеанс и остановите его.
2. Для проверки системного запроса согласия выберите **Забыть** для Adaptive DPI в настройках VPN Android, если этот пункт доступен. Подключите другой VPN. Вернитесь в Adaptive DPI и проверьте уведомление на главном экране. Нажмите кнопку запуска, затем **Отмена**. Другой VPN должен остаться активным.
3. Снова нажмите запуск и выберите **Переключиться**. Если появится системный запрос, сначала отклоните его и проверьте, что Adaptive DPI не создал TUN. Повторите попытку и подтвердите запрос. Ранее выбранный режим должен запуститься без второго нажатия. Android может переключить VPN без запроса, если согласие уже сохранено.
4. Остановите Adaptive DPI и включите **Постоянная VPN** для другого приложения. Повторите попытку с включённым и выключенным параметром **Блокировать подключения без VPN**. При отказе Android проверьте объяснение и переход по кнопке **Настройки VPN**. Верните параметры в исходное состояние вручную.
5. Запустите транспорт Adaptive DPI и подключите другой VPN из его приложения. Проверьте в журнале отзыв разрешения, освобождение TUN и ноль активных соединений. После завершения остановки быстро нажмите запуск несколько раз. В журнале новый запуск должен иметь один идентификатор сеанса и одно успешное создание TUN.
6. Повторите переключение с выбранным режимом **Трафик приложения**. Проверьте передачу в Chrome по инструкции выше и остановку транспорта.

Если другой VPN исключает Adaptive DPI из своих маршрутов, Android может не показать его в сети по умолчанию приложения. Штатный системный запрос остаётся доступен при запуске. Публичные API не раскрывают причину каждого отклонённого запроса и настройки Always-on другого приложения. [Android VpnService](https://developer.android.com/reference/android/net/VpnService) · [Сеть по умолчанию](https://developer.android.com/reference/android/net/ConnectivityManager#getActiveNetwork())
