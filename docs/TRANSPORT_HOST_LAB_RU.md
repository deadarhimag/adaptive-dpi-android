# Контрольный сетевой стенд этапа 3

Вариант Windows выполнен на Python 3.13, localhost, без изменений firewall и системных настроек. Фикстура использует временный сертификат, которому явно доверяет только TLS-клиент стенда. Приватный ключ остаётся вне Git. Стенд открывает динамические порты только на 127.0.0.1.

Сначала создать краткоживущий сертификат для localhost в отдельном временном каталоге OpenSSL с SAN `DNS:localhost`. Запустить из корня репозитория:

```text
python -B scripts/transport-host-lab.py --certificate <cert.pem> --key <key.pem> --report <новый-отчёт.json>
```

Отчёт содержит число совпадений, число переданных байтов, длительность, HTTP-код и SHA-256 контрольного тела. Ошибка содержимого или незавершённый рабочий процесс завершают команду ошибкой. После прогона удалить тестовый ключ. Для Linux подготовлен отдельный workflow со своим временным сертификатом и нативными тестами через ASan/UBSan. Android CI от него не зависит.

## Выполненный Windows-прогон

| Сценарий | Результат |
| --- | --- |
| 8 параллельных TCP | 8/8 точных ответов, 65 536 байт в каждом направлении, 46,411 мс суммарно |
| 16 параллельных TCP | 16/16, 131 072 байта, 64,273 мс |
| 32 параллельных TCP | 32/32, 262 144 байта, 105,067 мс |
| UDP | 32/32 точных ответов по одному UDP-сокету, 8224 байта в каждом направлении |
| HTTPS | 200, совпал SHA-256 контрольного тела |
| Явный отказ HTTPS-фикстуры | 451, отдельный результат |

Это измерения локального тестового сервера. Производительность Android TUN, FD, потоки HEV и очередь релея этими числами не характеризуются. Ближайший план измерений транспорта — повторить матрицу 8/16/32 и слегка выше 32 на AVD, с/без активной диагностики. Замерять максимальное число активных соединений, потоки и FD до/во время/после Stop, медиану и хвост задержки. Тайм-ауты TCP connect, TCP idle, UDP read, DNS, аутентификации и очистки анализировать раздельно. Прежний Android 14 прогон подтвердил TCP idle около 60 с и отсутствие накопления ресурсов в 10 циклах. [Контрольный CI](TRANSPORT_VALIDATION_2.4.6_RU.md#android-ci-331-контроль-после-исправления)

## Ограничения измерений

На Windows Server 2019 нет доступных WSL, Docker, tcpdump и tshark. Открытие raw IPv4 socket для тестового захвата завершилось `WinError 10013` до привязки к loopback. PktMon установлен, но его команда status не получила состояние. PCAP отсутствует, отчёт содержит `capture.status=not_measured`. Приложение и стенд не требуют изменения правил фильтрации хоста.

Сценарий отказа реализован HTTP-сервером, без моделирования инспекции пакетов. Неполный ClientHello, разбиение по TLS records, повреждённые данные и прекращение передачи во время накопления проверяются на JVM. Для анализа реальных сегментов нужен изолированный Linux с разрешённым пассивным захватом синтетической пары адресов. Тогда отдельно считать отправленные сегменты, повторные передачи, ACK, TLS records и контрольное содержимое. Измерение выполняется в точке, где видна фактическая сегментация, а влияние TSO/GSO/GRO фиксируется в отчёте. Границы вызовов read/write дают доказательство только на уровне приложения.

NDK 28.2.13676358 с Clang 19 собрал нативный тест для Android arm64-v8a и x86_64 (API 29). Хостовая линковка Windows завершилась ошибкой отсутствующих библиотек MinGW. Linux host-тест, JNI-вызов, ASan/UBSan и AVD остаются отдельными проверками. ADB не обнаружил устройств, драйвер ускорения эмулятора отсутствует.
